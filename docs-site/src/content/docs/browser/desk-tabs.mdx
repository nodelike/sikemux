---
title: Desk tabs
description: "Each agent's browser tabs, beside its chat."
---

Every agent has a **desk**: the pane beside its chat where it opens pages, files and task terminals for you. `⌘J` shows or hides the desk of the agent in front.

The switch at the desk's top left picks what it shows: **Browser**, **Files**, **Terminals** or, on a Mac, **iOS Simulator**. The strip lists that kind's tabs only, and a kind you go back to shows the tab it last showed. **Files** and **Terminals** are greyed while the agent has opened none, and **Browser** takes the agent's colour while the agent works in a page and you look at something else.

**iOS Simulator** shows the device the agent attached. Before it attaches one, the desk shows a device already running, else an iPhone; click the device's name to pick another, and **Start** to boot one that is off. Beside Home, Lock and Turn, its bar saves a screenshot to the Desktop and shuts the device down, asking first while an agent is using it. The agent's simulator tools then use the device you picked.

A page's tab shows a spinner in place of its site icon while it loads. The bar over the page has back, forward and reload (`⌘[`, `⌘]`, `⌘R`) and the page's address, and **+** beside the tabs (`⌘⇧T`) opens a new one. Right-click a tab to close it, copy a page's link, or copy a file's path or relative path, or reveal it in Finder.

`⌘L` opens an address field over the middle of the page, which dims under it. As you type, it finishes a site you have visited before and lists the pages that match, with a Google search when what you typed reads as one. With nothing typed it lists the sites you visit most. The arrow keys pick a row, Return opens it, and Escape or a click anywhere else closes the field.

When you ask an agent to open, show or preview a page, it opens the page on its desk rather than in your own browser, so you watch the same page it reads.

A link in an agent's reply opens on its desk too; `⌘`-click opens it in your own browser instead. A link to a pull request on GitHub, Bitbucket or GitLab opens as the pull request itself, drawn as the Git tab draws one, among the Browser tabs: its files, commits, checks, conversation and diffs, with review, merge and, for the project's own repository, Check out. When no account is signed in to that host, or it can't read the pull request, the link opens as its web page. Links to an issue on those hosts, or to a run of GitHub Actions, open the same way, as the issue or the run with its jobs and logs. A link to a Jira issue on a site you're signed in to opens the same way, as the issue itself.

## What tabs open

- `http` and `https` pages.
- Local files and folders: give the agent an absolute path, a `~/` path or a `file://` URL; a folder opens its `index.html`. Sikemux serves the page from a private address on your computer. Inside a git project, the files beside it load too, so relative links and images work. Anywhere else, including Downloads, Desktop and other folders that gather files from anywhere, a page sees only itself. Folders are never listed.

## Downloads

Files a page downloads wait in a folder of Sikemux's own, marked as downloaded from the internet, and Sikemux shows a notice for each. Click **Keep in Downloads** to move it into your Downloads folder and show it in Finder; files you don't keep are cleared after a week. A page that starts more than eight downloads in half a minute is stopped.

## Size

A tab's page follows the pane's size. An agent can hold a tab at a set size, such as phone (390×844), tablet (820×1180) or desktop (1280×800), to check a layout. The page is scaled down to fit the pane, never up. The phone size also sends iPhone Safari's user agent, so sites serve their phone version.
