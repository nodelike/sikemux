title: Databases

---

Agents reach the databases you saved by name: they list them, read their tables and run SQL. Each agent gets a connection of its own, read-only unless you switch on **Agents may change data** for that database in **Settings → Connectors**. Switch on **Production** beside it too, and every statement an agent runs there while it may change data waits for you to allow it first, under **Decide** in Goals ([what leaves this machine](/agents/permissions/#what-leaves-this-machine)); reading a production database it can't change never asks. That page also lists every saved database, with **Remove** beside each.

## When an agent adds one

An agent can't save a database itself. When it sets one up for you, such as a read-only role, it proposes it instead, and Sikemux asks you first:

1. Sikemux reads the agent's connection URL and tries it. A URL it can't read, a server URL without its password, a server it can't reach or a name you already use goes back to the agent, and you're asked nothing.
2. A card asks you whether to add it, showing its name, engine, `user@host:port/database` and how many tables it found. It never shows the password.
3. **Add** saves it, with any password in the Keychain. **Don't add** turns it down.

A database an agent adds opens read-only and agents can't change its data. Only you can change that, in **Settings → Connectors**.

The card goes to you, never to another agent, and you can answer it in the app, on the notch or on your phone.
