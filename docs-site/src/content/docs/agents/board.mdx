description: "Cards your agents work from, and slices that only pass on evidence Sikemux collected itself."

Each project has a board of cards, open with `⌘⌥6`. You and your agents add cards, an agent claims one and works it, and a card can sit under another or wait on others. Agents use the `board_add`, `board_claim`, `board_update` and `board_list` tools.

The same work never gets two cards. A Jira or Linear ticket you put on the board again, while its card is still open, goes to that card, and so does a board trigger that fires again, with what came with it, such as a webhook's request. The card keeps the last eight such arrivals, and the agent working it, or its team's lead, is told. A ticket put on the board again after its card is done gets a new card, and its open subtasks move under it.

When the project's check is its CI, CI failing the same way on two runs in a row of the project's branch puts the failure on the board. What failed is known by its workflow and job, and by the test when the job's log names one (as cargo, nextest, Go, pytest and Vitest do); a job whose log can't be read counts as the same failure as any test under it. If an open card already holds that failure, it goes there as an arrival with what CI printed, and the card's agent or its team's lead is told. Otherwise Sikemux files one card for everything that commit broke: a slice that promises CI passes on the branch again, with the failing output as its first check run. Auto picks it up when it's on. A run that passes starts the count again, and so does marking a CI card done or deleting it, so a failure you dismiss comes back only after two more failing runs. When CI's logs can't be read in time, that run doesn't count either way.

## Slices

A card that makes a **promise**, one sentence saying what it changes, is a slice. A slice goes up three gates before it is done:

| Gate | Who passes it | What it needs first |
| --- | --- | --- |
| **Built** | The agent that holds the card | The project's check passed on the agent's latest commit |
| **Looks right** | You | Built |
| **Landed** | Sikemux, or you when the project says so | Looks right, and the slice's commits on the branch |

An agent saying a slice is done passes nothing by itself. When it marks the card done, Sikemux looks at the latest check run on the agent's latest commit. If that run failed, or the agent committed nothing, the card stays in progress and the agent is told why. If the check has not run on that commit yet, Built passes by itself once it does, and the agent hears. Sikemux reads the agent's latest commit from git each time before Built passes, so a commit it didn't hear about can't slip through. In the project's own checkout with commit attribution off, git can't tell whose a commit is, so Sikemux goes by the latest commit it saw the agent make with `git_commit`. A project whose `sikemux.json` names no `check` can't pass Built. The check is a command Sikemux runs, or the project's CI, which counts only once the agent's commit is on the project's branch and pushed; see [the project's check](/getting-started/projects/#the-projects-check).

A check command runs on commits on the project's branch, so an agent in a checkout of its own lands its commits before Built can pass; so does CI, once the project's branch is pushed. Work can land before you look at it; Landed passes as soon as you pass Looks right, unless the project lands only when you say.

## When slices land

Each project says once who passes Landed, under **Lands** in the board's settings or **Slices land** on a goal:

- **Once on the branch**: Sikemux passes Landed as soon as the slice's commits are on the project's branch, and Auto merges its pull requests itself once their checks pass and a reviewer approves.
- **When you pass it**: nothing counts as landed until you pass Landed yourself. Auto leaves its pull requests open for you to merge, and merging one passes Landed as yours. An agent can still land its own commits with `git_commit`, but its slice then waits for you at Landed. A new commit on a slice that isn't done yet undoes Built and Looks right, so you never pass work you didn't see. Marking a slice done yourself passes every gate it has left, and moving it back to Open clears them. A Jira ticket closed with nothing of its slice landed doesn't close the slice either: it waits for you under **Decide**, saying the ticket says done but nothing landed, until you pass Landed, mark the slice done, or the ticket is opened again. Auto doesn't start an agent on it meanwhile.

## Assertions

A goal can say, before its slices are cut, what must hold once they're done, so the checks aren't shaped by the work. Each assertion is one sentence and the evidence that shows it, which Sikemux collects itself: the project's check passing, a named CI workflow passing, a browser recording, or a screenshot of a page. You or the agent leading the goal writes them, with `board_assert`; once a slice that fulfils one has started, only you can change it.

A slice names the assertions it fulfils. Built then also needs evidence of each one's kind on the slice's latest commit: the project's check passing on it, its workflow passing on the pushed tip of the project's branch once that holds the commit (a re-run that passes counts after one that failed or was cancelled), or a recording or screenshot the agent took while the slice was its card. When a screenshot is kept this way, Sikemux also takes the same page at a phone's width (390 px) and a tablet's (820 px), by resizing it only, so nothing reloads, then puts the tab back as it was, so you see all three; a newer screenshot replaces all three. You judge recordings and screenshots at Looks right. An assertion that's retired, or whose goal goes, no longer binds the slice, which shows it as detached; moving a slice to another goal frees it of its assertions until they're named again.

When Built is refused because the project's check failed, Sikemux files the fix as a card under the slice, held by the same agent, and the slice waits on it. A later failure goes to the same card while it's open. Once the fix card is done, the agent marks the slice done again.

## Cards Auto runs

When Auto takes a card, the card becomes a slice, promising what its title says unless it already makes a promise. Shipping its work counts as the agent saying it's done, and Built passes once the pull request's checks pass on the commit Auto pushed.

- When the project's slices land once on the branch, Auto merges the work itself once its reviewer approves, and the card has no Looks right gate: it passes Built, then Landed when it merges.
- When they land only when you pass it, Auto leaves the pull request for you to merge, and the card waits for you at Looks right with its pull request. Merging it yourself passes Looks right and Landed as yours.

A pull request Auto opens lists the slice's evidence on its latest commit in the description: each check run and how it went, the change, and the screenshots and recordings by name. The files themselves stay with the card on the host that took them, since no code host takes them.

When Auto gives a card back, the inbox says what it needs from you: something to fix, such as checks that failed again after a fix or a merge that didn't go through, or something only you can unblock, such as an agent that stopped running. **Ship it again** on the card starts Auto on it again.

## Evidence

Sikemux collects a slice's evidence itself:

- each run of the project's check on the agent's commits, with its output, passed or failed
- the change the agent's latest run of commits makes, once Built passes
- the browser recordings the agent makes while it works the card

A slice keeps its latest 24 pieces of evidence, and every piece you wrote a note on.

## When a slice needs you

A slice waiting at **Looks right** shows in the inbox as something to decide, with its promise and recordings, and in the board's **Needs you** column. Pass it once it looks right. If it needs more work, write a note on the slice, or on one piece of its evidence: the note goes to the agent whose work that piece shows, else to the agent that holds the card, as a message from you, and the slice waits at Looks right until the agent sends new work.
