---
title: The agent board
description: "Cards your agents work from, and slices that only pass on evidence Sikemux collected itself."
---

Each project has a board of cards, open with `⌘⌥6`. You and your agents add cards, an agent claims one and works it, and a card can sit under another or wait on others. A card that waits on a slice can start as soon as that slice is **Built** on the project's branch, without waiting for you to look at it, and a change you ask for after that is new work it doesn't wait for. Whoever added a waiting card, or else its goal's lead, hears when it can be claimed. Agents use the `board_add`, `board_claim`, `board_update` and `board_list` tools.

The Done column draws its newest 200 cards, and its count includes the rest. **Find a card** searches all of them.

The board tidies itself without asking you:

- A finished card moves to the project's archive three days after it finished, once nothing is under it, nothing runs on it and its ticket knows it's done.
- A card whose cards under it are all done is marked done too, saying so, unless an agent is working it, it has a ticket, or its goal still waits for you to look at it.
- An open card nobody holds that hasn't changed for seven days moves to **Later** and leaves the board, on the Mac and the phone, along with the counts of cards under a card. Pick **Later** next to **Needs you** to see those cards and how long each has been aside. A card comes back once someone claims or changes it, a card that waits on it gets an agent, or you drag it to a column. Nothing in Later is ever deleted.

While an agent holds a card, only it and the agents above it can change it or take it. Once that agent closes, its card counts as nobody's, so any agent can finish it or claim it and it never stays stuck. A card under another goes back to Open by itself when its agent closes, stops, or sits idle with it for 30 minutes while nothing it waits on can bring it back, with a line such as "@Thistle left it unfinished." A slice goes further and tells you: see [when an owner stalls](/agents/goals/#when-an-owner-stalls).

The same work never gets two cards. A Jira or Linear ticket you put on the board again, while its card is still open, goes to that card, and so does a board trigger that fires again, with what came with it, such as a webhook's request. The card keeps the last eight such arrivals, and the agent working it, or its team's lead, is told. A ticket put on the board again after its card is done gets a new card, and its open subtasks move under it.

When the project's check is its CI, CI failing the same way on two runs in a row of the project's branch puts the failure on the board. What failed is known by its workflow and job, and by the test when the job's log names one (as cargo, nextest, Go, pytest and Vitest do); a job whose log can't be read counts as the same failure as any test under it. If an open card already holds that failure, it goes there as an arrival with what CI printed, and the card's agent or its team's lead is told. Otherwise Sikemux files one card for everything that commit broke: a slice that promises CI passes on the branch again, with the failing output as its first check run. Auto picks it up when it's on. A run that passes starts the count again, and so does marking a CI card done or deleting it, so a failure you dismiss comes back only after two more failing runs. When CI's logs can't be read in time, that run doesn't count either way. If an agent already owns mending that failure, it holds the card, so one failure is one piece of work.

## Slices

A card that makes a **promise**, one sentence saying what it changes, is a slice. A slice goes up two gates before it is done:

| Gate | Who passes it | What it needs first |
| --- | --- | --- |
| **Built** | The agent that holds the card | The project's check passed on the agent's latest commit |
| **Landed** | Sikemux, or you when the project says so | Built, and the slice's commits on the branch |

Whether the work looks right is asked once for its whole goal, and only when it changes what people see; see [looking once at a goal](/agents/goals/#looking-once-at-a-goal).

A project with [environments](/agents/goals/#environments) has a different ladder: Built, then a step for each environment.

An agent saying a slice is done passes nothing by itself. When it marks the card done, Sikemux looks at the latest check run on the agent's latest commit. If that run failed, or the agent committed nothing and gave no result, the card stays in progress and the agent is told why. If the check has not run on that commit yet, Built passes by itself once it does, and the agent hears. Sikemux reads the agent's latest commit from git each time before Built passes, so a commit it didn't hear about can't slip through. In the project's own checkout with commit attribution off, git can't tell whose a commit is, so Sikemux goes by the latest commit it saw the agent make with `git_commit`. A project whose `sikemux.json` names no `check` can't pass Built. The check is a command Sikemux runs, or the project's CI, which counts only once the agent's commit is on the project's branch and pushed; see [the project's check](/getting-started/projects/#the-projects-check).

A check command runs on commits on the project's branch, so an agent in a checkout of its own lands its commits before Built can pass; so does CI, once the project's branch is pushed. Work lands before you look at it: Landed passes once Built has and the commits are on the branch, unless the project lands only when you say.

A slice whose work makes no commit, such as a deploy, has nothing for Built to check. Its agent closes it by marking it done with a result saying what it did and what showed it worked, which passes every gate it has left as the agent's, without asking you. The agent is told so in its board listing and again when a deploy of its ends, and the slice's page names the agent, not a check, as what it waits on. A slice bound to assertions still needs their evidence on a commit.

## When slices land

Each project says once who passes Landed, under **Merge** in the board's Auto settings or **Slices land** on a goal:

- **By itself**: Sikemux passes Landed as soon as the slice's commits are on the project's branch, and Auto merges its pull requests itself once their checks pass and a reviewer approves. Agents push and merge without asking you; deploys still wait for you ([what leaves this machine](/agents/permissions/#what-leaves-this-machine)).
- **When you pass it**: nothing counts as landed until you pass Landed yourself. Auto leaves its pull requests open for you to merge, and merging one passes Landed as yours. An agent can still land its own commits with `git_commit`, but its slice then waits for you at Landed. Its pushes and merges wait for you to allow each once ([what leaves this machine](/agents/permissions/#what-leaves-this-machine)). A new commit on a slice that isn't done yet undoes Built, so you never pass work you didn't see. Marking a slice done yourself passes every gate it has left, and moving it back to Open clears them. A Jira ticket closed with nothing of its slice landed doesn't close the slice either: it waits for you under **Decide**, saying the ticket says done but nothing landed, until you pass Landed, mark the slice done, or the ticket is opened again. Auto doesn't start an agent on it meanwhile.

## Assertions

A goal can say, before its slices are cut, what must hold once they're done, so the checks aren't shaped by the work. Each assertion is one sentence and the evidence that shows it, which Sikemux collects itself: the project's check passing, a named CI workflow passing, a browser recording, a screenshot of a page, or a command exiting with success. You or the agent leading the goal writes them, with `board_assert`; once a slice that fulfils one has started, only you can change it. A command an agent writes doesn't run or count until you accept that exact command; see [Goals](/agents/goals).

A slice names the assertions it fulfils. Built then also needs evidence of each one's kind on the slice's latest commit: the project's check passing on it, its workflow passing on the pushed tip of the project's branch once that holds the commit (a re-run that passes counts after one that failed or was cancelled), its command exiting with success in a clean checkout of it, or a recording or screenshot the agent took while the slice was its card. When a screenshot is kept this way, Sikemux also takes the same page at a phone's width (390 px) and a tablet's (820 px), by resizing it only, so nothing reloads, then puts the tab back as it was, so you see all three; a newer screenshot replaces all three. You judge recordings and screenshots when you look at the goal. An assertion that's retired, or whose goal goes, no longer binds the slice, which shows it as detached; moving a slice to another goal frees it of its assertions until they're named again.

When Built is refused because the project's check failed, Sikemux files the fix as a card under the slice, held by the same agent, and the slice waits on it. A later failure goes to the same card while it's open. Once the fix card is done, the agent marks the slice done again. Each commit gets one fix card: if the check failed on the same commit after its fix card was done, no second card is filed, and the agent is told to mend it with a new commit.

## Cards Auto runs

Auto takes any card that nobody holds and nothing holds up, whoever added it, the highest priority first and then the oldest. Only cards from a project's [reservoir](/getting-started/projects/#the-reservoir) have a priority, so that command can keep Auto supplied with work you never had to add. A project's [standing roles](/getting-started/projects/#standing-roles) add cards of their own as commits land, and Auto runs those the same way. A card an agent added waits until that agent's team is through with it: while its lead or any of its workers is in a turn, the card stays for them. Auto runs up to 64 agents at once in a project, counted together with the agents agents started.

Auto keeps itself from running away without asking you. One run can have at most 16 unfinished cards of its own on the board, and a card added by a run that itself came from such a card rests once more than three unfinished runs stand above it, until one finishes. When a board nears 1000 cards, its oldest finished cards move to the archive at once, without waiting their three days.

When Auto takes a card, the card becomes a slice, promising what its title says unless it already makes a promise. Shipping its work counts as the agent saying it's done, and Built passes once the pull request's checks pass on the commit Auto pushed.

- When the project's slices land once on the branch, Auto merges the work itself once its reviewer approves: the card passes Built, then Landed when it merges.
- When they land only when you pass it, Auto leaves the pull request for you to merge, and the card waits for you at Landed with its pull request. Merging it yourself passes Landed as yours.

Either way, a card whose work changes what people see asks you to look at it once it is Built, as any goal does.

Where Auto merges the work itself, the agent starts by proposing a contract on the card: the behaviours it will build and how each can be verified. A fresh agent on another CLI reviews that against the card, for up to three rounds, and then the agent's latest proposal stands. Nobody asks you about it, and you can read it on the card. A contract only ever adds to your acceptance criteria; it can't weaken or replace them.

Before Auto merges, an agent on another CLI reviews the change blind, against the card, your acceptance criteria and the contract. The reviewer builds the exact commit in a copy of its own and uses it as a person would, with processes, the browser, the simulator or the CLI. A change with nothing to run, such as documentation, is only read. Only a few reviewers that build run at once, by the size of the machine, so they don't starve the agents and checks; the others wait, longest-waiting first, and the card says it is waiting for a reviewer's place. A review that only reads never waits. A reviewer that says nothing for 30 minutes in the middle of its review comes back to you, so it can't hold its place for good. Its verdict grades each criterion and lists what it tried, and an approval that tried nothing on a change that can run is refused. If the change falls short, its agent gets the failures with their files and lines and fixes them, and a fresh reviewer looks again. Only an approval of the exact commit can merge.

Where Auto merges the work itself, an approved change waits its turn in a merge queue for its base branch, so two changes that each pass alone can't both land and break it together. It merges only once its check has passed on top of the latest base. When the project's check is a command, changes that wait together go on one stack of up to 8 and take one check run, in a checkout of the queue's own, and each lands in turn so long as the branch is still what was checked. If that run fails, Sikemux finds the change that broke it and sends only that one back; the others stay in line. When the check is the project's CI, each change is rebased, pushed and waited for one at a time. A clean rebase keeps the reviewer's approval if the patch is unchanged, including the lines around it; a rebase that changes the patch gets a new review. A failure or conflict gets one fix from the change's own agent, and then the card comes back to you. If the base itself fails, nobody is sent back: each waiting change is tried on it alone, and the first that makes it pass lands. Changes that don't wait for the base to move. Projects where you land the changes yourself have no queue, and the run record keeps queue time and how many times a change was sent back.

A slice's pull request can carry its proof in its description, in one short block under what the description already says: the slice's promise, the one piece of evidence its gate leads with, each check on its latest commit as one pass or fail line, and **Open slice in Sikemux** for everything else. Sikemux finds the pull request by the slice's latest commit, or it is the one Auto opened. Before the first write to each pull request it asks you, on behalf of the slice's agent, showing the exact block: **Post** writes it and keeps it up to date in place whenever the evidence, a check or the commit changes, leaving the rest of the description alone; **Skip** never writes to that pull request. When the block has a screenshot, **Post** also keeps it where the code host shows it from: GitHub on a `sikemux-evidence` branch of the repository that holds nothing else, GitLab in the project's uploads, Bitbucket in the repository's downloads. An agent sees the block its pull request holds, or would hold, in `board_list` for its card.

When Auto gives a card back, the inbox says what it needs from you: something to fix, such as checks that failed again after a fix or a merge that didn't go through, or something only you can unblock, such as an agent that stopped running. **Ship it again** on the card starts Auto on it again.

Each new worktree Auto makes for a card runs the commands in `worktree.onCreate` in `sikemux.json` before its agent starts. If they don't finish, the agent is told why and carries on.

Auto keeps a card moving when its agent fails. If a turn fails, the agent's process dies, or it says nothing for 30 minutes in the middle of a turn, Auto brings it back on its own session in the same worktree, and starts a fresh agent there with a handover when that cannot work. It tries up to three times, 30 seconds, 2 minutes and 8 minutes apart, and gives the card back to you once with the reason when the same failure comes twice in a row or the tries run out. Stopping or closing an agent yourself is never undone, a usage limit waits for its reset, and a sign-in or missing program comes to you at once. The card's run record keeps how many times this happened and why.

A small change gets a reviewer who only reads it, and a short card that names the few files it changes skips the contract round. The run record says why. A change that touches or mentions credentials, migrations or how changes merge and ship, or that sits where work broke or reviewers asked for changes before, keeps the full path.

Every card keeps a record of its Auto run. An agent can ask the board to compare a project's records where Auto merged the work with those where you did: cost, rounds, time, progress holds and how often work broke after landing, with how many runs each figure rests on, so a thin comparison says it is thin. It also lists the cards a reviewer approved that then broke, with what the reviewer said, and the cards you overruled.

Where Auto merges the work itself, it pushes a card's commits as they are made to a private ref of its own, outside the project's branches and tags, so it starts no CI run and shows up in no branch list. The ref is removed when the card's worktree is. If the card's worktree goes missing, Auto makes it again at its last pushed commit, runs the project's worktree setup and puts a fresh agent on it, saying that uncommitted work is gone. With nothing pushed, the card starts again from the latest base, and the card says so. Where you merge the work yourself, nothing is pushed and a lost worktree gives the card back to you. Pushing is never forced over anything Auto did not put there.

Auto holds a card that spends without getting anywhere. Cost alone never stops a card: what counts is what a run has spent since it last made progress, meaning a check passing on new commits or a reviewer newly passing a criterion, and landing ends the run. So a run that keeps passing checks is never held, however much it costs. A run is held when it spends $50 without progress, or twice what the project's finished cards usually cost once five have finished, between $20 and $150. Claude reports what it costs, as does any agent that sends a cost; for an agent that doesn't, four hours of agent time stands in for the money. A run is also held when the same failure comes back: its pull request's checks or a reviewer's failed criteria two rounds in a row, or the project's check three times in a row. Only that card is held, with the reason on it, and other cards keep running. A fresh agent then takes over in the same worktree, and if it gets no further the card comes to you. The run record counts each hold and its cause.

**Hosts** lists the computers linked with this one, and appears once there are any. Pick the ones Auto may use: once this computer's places are full, cards go to the first with room, each taking as many agents as this one, signed in as that computer's own agent accounts. The card's worktree stays on this computer. Each time the agent's turn ends its commits come back there, and the pull request, checks, reviewer and merge queue run here as usual, so those still use this computer's sign-ins and time. An agent on another computer has no contract step and doesn't update the board: its final answer becomes the card's result. If that computer goes out of reach, the card waits for 30 minutes, then a fresh agent carries on here from the commits that came back. Work it hadn't sent back stays on that computer. If you unlink the computer, a fresh agent takes over within a couple of minutes.

**Spend ceiling** is the most Auto may spend in a project. It is off by default, and only what agents report costing counts towards it. Once it's reached Auto starts no new cards, the Auto panel says why, and cards already running finish. Raising the ceiling picks things back up.

## Evidence

Sikemux collects a slice's evidence itself:

- each run of the project's check on the agent's commits, with its output, passed or failed
- the change the agent's latest run of commits makes, once Built passes
- the browser recordings the agent makes while it works the card

A slice keeps its latest 24 pieces of evidence, and every piece you wrote a note on.

## When a slice needs you

A slice waiting at a gate only you pass, such as **Landed** where you land slices or an environment's step, shows in the inbox as something to decide, with its promise and recordings, and in the board's **Needs you** column. Pass it once it is ready. If it needs more work, write a note on the slice, or on one piece of its evidence: the note goes to the agent whose work that piece shows, else to the agent that holds the card, as a message from you. The slice then goes back to the agent that holds it and leaves **Needs you**: it climbs again from Built once the agent commits what you asked, or answers you, and marks it done again.

A goal whose work changes what people see waits for you to look at it once, on its own card in the **Needs you** column; see [looking once at a goal](/agents/goals/#looking-once-at-a-goal).
