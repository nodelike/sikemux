title: Linked hosts
description: "Agents that start workers on your other hosts, and the sign-ins they use there."
---

Every host signed in to your account links with every other on its own, so an agent on one starts workers on another. A host that turned on **Require approval for new devices** asks you first. Removing a host from your account unlinks it everywhere.

A worker on another host runs there on that host's own sign-in for its CLI, in a checkout of its own. Its commits come back to a branch in the lead's checkout each time its turn ends. A lead or worker that went to sleep stays on its team and wakes when its teammate writes to it; only closing an agent takes it off.

## Sign-ins

An agent uses the sign-ins of the host it runs on, whichever host started or messaged it: that host's [connectors](/agents/connectors/) such as Jira, GitHub, AWS or Slack, its saved databases and its browser tabs. A worker on another host gets that host's sign-ins. A sign-in from your [account vault](/agents/connectors/#account-vault) reaches another host only once you allow that host to use it.

## Sending a project to another host

**Settings → General → Session transfer** sends the project in front to another host you've linked, with its chats and tabs. Pick the host, then:

- **Copy** leaves the project here as it is.
- **Move** closes its chats here and removes their saved conversations, but only once the other host has every chat and tab. If anything doesn't arrive whole, nothing here changes.

Tick **Bring uncommitted changes** to take the checkout's uncommitted work along. Chats come along when their agent keeps them in files, as Claude Code and Codex do; the others stay here. A chat that came along runs on the other host's sign-in the next time you send to it. Sikemux then says what went and what stayed, and opens the project on the other host.

When the other host already has a checkout of the repository, the session goes into it only if it is on the same branch and commit, and, when uncommitted changes come along, has none of its own. Otherwise nothing is sent, and **Into a worktree** sends it into a new worktree of that checkout at this host's commit instead. A commit the other host lacks comes over from here.
