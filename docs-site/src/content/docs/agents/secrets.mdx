---
title: Secrets from 1Password
description: "Keep a key or token in 1Password and give Sikemux only its op:// reference."
---

Anywhere Sikemux asks for a key or token, you can enter a 1Password secret reference instead, such as `op://Work/OpenRouter/credential`. Copy it in 1Password with **Copy Secret Reference**. Sikemux keeps only the reference and reads the secret with 1Password's CLI, `op`, when it needs it. The secret never shows in Sikemux, and no agent sees it.

It works for:

- a [model provider's](/agents/providers/) API key;
- a GitHub, GitLab or Bitbucket token, in [Connectors](/agents/connectors/);
- a variable an [account](/agents/accounts/) forwards from your shell, when the shell sets it to a reference;
- your answer to a call that asks for a secret or for access: Sikemux reads it once, when you answer, and hands the agent the secret as it hands any other.

## Set up `op`

Install the [1Password CLI](https://developer.1password.com/docs/cli/get-started/) on the computer that runs the agents, and sign it in. With the 1Password app's CLI integration on, the app asks for your fingerprint when Sikemux first reads a secret; Sikemux waits 45 seconds for it.

On a [linked host](/agents/linked-hosts/) or a server nobody sits at, sign `op` in with a [service account](https://developer.1password.com/docs/service-accounts/) (`OP_SERVICE_ACCOUNT_TOKEN`) or point it at a [Connect server](https://developer.1password.com/docs/connect/) (`OP_CONNECT_HOST` and `OP_CONNECT_TOKEN`) in your shell's profile. Sikemux runs `op` with your shell's environment, so it uses whichever `op` would.

## When a secret can't be read

If 1Password is locked, signed out or has nothing at the reference, Sikemux says so where the secret was needed: adding a provider or connector fails with 1Password's reason, and a call stays open so you can unlock 1Password and answer again. Sikemux never keeps a different credential in its place.

A provider key is read the first time it's used and kept in memory until Sikemux quits. After changing it in 1Password, connect the provider again.
