---
title: Updates
description: "Stable and nightly channels, and how Sikemux updates itself."
---

On a Mac, and from the AppImage on Linux, Sikemux keeps itself up to date. Choose how new in **Settings → About → Updates**:

| Channel | What you get |
|---|---|
| **Stable** | The latest signed release |
| **Nightly** | The newest signed build, prerelease or stable |

When an update is out, the foot of the side rail says so, then shows how its download and install are going. Click it for the release's notes and **Install**.

Sikemux looks for an update every half hour, and **Check now** looks straight away. When a check fails, such as while you are offline, **Last checked** says why.

If Sikemux's servers stop working with the version you have, **Update Sikemux** covers the window. Remote access and your account stay off until you update; you can also quit from there.

## Linux

The AppImage updates itself like the Mac app.

The `.deb` and `.rpm` are updated by the installer that put them in place. When a new release is out, **Settings → About** shows it with **Copy command**. Run the copied line in a terminal:

```bash
curl -fsSL https://sikemux.com/install | sh -s -- --app
```

On the nightly channel, the line sets `SIKEMUX_CHANNEL=nightly` before `sh`.

## On a server

A server running just the core keeps itself up to date too, on the channel it was installed from, or on nightly if you choose it for that host. Each time it finds a newer release, and once no chat on it is in a turn, it installs the release and restarts its core in place, so terminals and chats carry on. Before installing anything it checks that Sikemux signed that very release. The core runs as you and cannot replace its own file, so with systemd the installer sets up a small service that puts it in place as root.

`sikemux update` installs the newest release now, waiting only for chats in the middle of a request. `sikemux status` shows the version, whether the server updates itself, and when it last looked.

The server's row under **Hosts** shows the version it runs, or **update failed** when the last try did not work; its **⋯**, or the server's **⋯** in **Settings → Hosts**, says why.

To keep a server on the release it has, turn off **Update automatically** in either **⋯**, or run `sudo sikemux update --off` on it; `--on` turns updates back on. Only you can change this, so an agent on the server cannot pin it or unpin it: plain `sikemux update --on` or `--off` only says how. While updates are off, nothing installs, not even with `sikemux update`.

Once a server's release is too old for your account, the server stops reaching your devices and your account until it updates, and `sikemux status` says so. With updates on, it installs the newest release at once, without waiting for its chats.
