---
title: Updates
description: "Stable and nightly channels, and how Sikemux updates when you ask."
---

On a Mac, and from the AppImage on Linux, Sikemux tells you when a new build is out and installs it only when you ask. Choose how new in **Settings → About → Updates**:

| Channel | What you get |
|---|---|
| **Stable** | The latest signed release |
| **Nightly** | The newest signed build, prerelease or stable |

When an update is out, the foot of the side rail says so, then shows how its download and install are going. Click it for the release's notes and **Install**. Nothing downloads or installs, and Sikemux never restarts, until you click it.

Terminals and chats carry on through an update. A chat in the middle of a request holds the update up for at most two minutes. After that, the update goes ahead, and that chat stops and picks up again on its session. Once the update is in place, the windows restart to load it, waiting until you pause typing. Hover the rail's note to see which version you run and when it took over.

Sikemux looks for an update every half hour, or every five minutes on the nightly channel, and **Check now** looks straight away. When a check fails, such as while you are offline, **Last checked** says why.

If Sikemux's servers stop working with the version you have, **Update Sikemux** covers the window. Remote access and your account stay off until you update; you can also quit from there.

## Linux

The AppImage updates like the Mac app, when you click **Install**: its core asks root for each signed release, which replaces the core and the app unpacked beside it together.

The `.deb` and `.rpm` are updated by the installer that put them in place. When a new release is out, **Settings → About** shows it with **Copy command**. Run the copied line in a terminal:

```bash
curl -fsSL https://sikemux.com/install | sh -s -- --app
```

On the nightly channel, the line sets `SIKEMUX_CHANNEL=nightly` before `sh`.

On Arch Linux, pacman owns the app and Sikemux never replaces its files. When a repository pacman syncs from carries the package, the copied line is `sudo pacman -Syu`. Otherwise it is the installer line above, which updates `sikemux-bin` or `sikemux-nightly-bin` with `pacman -U`; the nightly package's line always sets `SIKEMUX_CHANNEL=nightly`.

## On a server

A server running just the core keeps itself up to date too, on the channel it was installed from, or on nightly if you choose it for that host. Each time it finds a newer release, and once no chat on it is in a turn, it installs the release and restarts its core in place, so terminals and chats carry on. Before installing anything it checks that Sikemux signed that very release. The core runs as you and cannot replace its own file, so with systemd the installer sets up a small service that puts it in place as root.

`sikemux update` installs the newest release now. It waits up to two minutes for chats in the middle of a request; any still busy after that pick up again on their sessions. `sikemux status` shows the version, whether the server updates itself, and when it last looked.

The server's row under **Hosts** says **updating** while an update is under way, or **update failed** when the last try did not work; its **⋯**, or the **⋯** on its detail on the **Devices** page, says why. Root writes how each update ended to `/usr/local/lib/sikemux/update-outcome.json`, so a failure is still there to read after the core restarts. A download only stops when it goes quiet for a minute, however slow it is.

The server keeps the core it replaced until the new one has run for half a minute. If the new core stops three times before then, it puts the previous one back and the row says **update rolled back**; that release is not installed again, and the next one is.

To keep a server on the release it has, turn off **Update automatically** in either **⋯**, or run `sudo sikemux update --off` on it; `--on` turns updates back on. Only you can change this, so an agent on the server cannot pin it or unpin it: plain `sikemux update --on` or `--off` only says how. While updates are off, nothing installs, not even with `sikemux update`.

Once a server's release is too old for your account, the server stops reaching your devices and your account until it updates, and `sikemux status` says so. With updates on, it installs the newest release and restarts into it at once, without waiting for its chats: the chats in the middle of a request stop and pick up again on their sessions once it is back, and its **⋯** says how many while it restarts.
