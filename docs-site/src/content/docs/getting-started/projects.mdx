title: Open a project

A project is a folder: its editor, terminals, Git and search all work in that directory. Open one with `⌘O`, or from a terminal with the `sikemux` CLI:

```bash
sikemux .
sikemux src/App.tsx:42:5
```

Install the CLI from **Settings → CLI**.

Sikemux is also listed under **Open With** in Finder and in apps that use it, such as Raycast. A folder opens as a project, and a text file opens in the editor of the repository it belongs to.

## Moving around

Swipe sideways with two fingers on the trackpad to move between a project's tabs, one tab per swipe.

The rail on the right has three pages, picked from the icons at its foot or by swiping across the rail:

- **Agents**: the project's chats, then the earlier ones.
- **Terminals**: every terminal open in the project.
- **Files**: the files open in the editor, then the project's file tree.

## A folder with several repositories

When the project folder is not a repository itself but holds several, such as `backend/` and `web/`, the Git pane lists them. Star one and it becomes the project's default: the Git pane opens it, the top bar shows its branch, the diff pane reviews it, and new agent worktrees are cut from it. When the folder holds only one repository, that one is used without asking. The choice stays on your Mac.

## Project settings

Each project has settings for how its code is built and run, apart from the app's. Open them with **Settings** at the foot of the project's tree in the sidebar; `Esc` or going anywhere else in the project closes them.

**Overview** opens first. It shows suggestions waiting for you, settings the project has moved past, such as a JDK chosen here after `pom.xml` started asking for a newer Java, with the change that fixes it, and **Health**: each folder's Done means and whether it last passed. **Check setup** runs them all; a failing one can go to an agent to fix.

**A page for each language** the project is written in: Java, Node, Go, Rust or Python, found from its build files. A project with several folders, such as `api/` and `web/`, gets one for each, like **Java · api**. Each setting reaches the tasks, terminals and agents started in that folder as the environment variable its tools already read, so an agent running `mvn` or `cargo` itself gets the same setup:

- **Java**: the JDK (`JAVA_HOME`), over the closest one to what the build asks for; Maven profiles (`MAVEN_ARGS`, Maven 3.9 or newer); Spring profiles (`SPRING_PROFILES_ACTIVE`) for a Spring Boot build; JVM options (`JDK_JAVA_OPTIONS`).
- **Node**: `NODE_ENV` and Node options (`NODE_OPTIONS`), with the version `.nvmrc` asks for.
- **Go**: Go flags (`GOFLAGS`) and private modules (`GOPRIVATE`).
- **Rust**: the toolchain (`RUSTUP_TOOLCHAIN`), the log filter (`RUST_LOG`) and backtraces.
- **Python**: import folders (`PYTHONPATH`) and unbuffered output.

**Environment** sets the variables of each folder. Sikemux finds environment files by what is in them and by what loads them (`dotenv` and `env-cmd` in package.json scripts, `--env-file`, docker-compose `env_file`, `.envrc`, a Makefile `include`), so `.env.stage`, `.environment.prod` and `config/dev.env` all count, and `.env.example` is shown but never read. Under **Load**, pick which environment's files the folder gets, or the files every environment shares; nothing is loaded until you pick, and a production-looking environment asks first. Variables you add win over the files', values that look like secrets stay hidden, and Sikemux never writes to the files.

**Load for agents**, on the same page, gives agents a different environment from yours, such as `local` while you use `stage`. An environment that looks like production (`prod`, `production`, `live`) never reaches an agent.

**Services** lists the services in the project's `docker-compose` files, whether each is running, with Start and Stop. Tick the ones a folder needs under **Started before tasks**, and Sikemux starts them, and waits until they are up, before any task in that folder runs.

**Tasks** lists what the project can run: the tasks in its `sikemux.json`, the ones only you have, and the ones found in its build files, with **Add a task** and **Find tasks with an agent**. Below them is what `sikemux.json` adds besides tasks, whether this Mac trusts it, with **Stop trusting** to have its commands ask again, and what is wrong with it when it is not valid.

**Done means** picks, for each folder, the tasks an agent's work must pass before it says it is finished, such as the tests. Agents start them themselves; by default only the folders an agent changed are checked, and an agent whose check fails fixes it and runs it again before telling you. You can have it stop and tell you instead.

**What agents know** shows the brief every agent working in the project reads in `workspace_inspect` before it builds, runs or tests anything: each folder's language and version, the settings above, the environment loaded (secret values never), the tasks, and Done means. Your own notes for agents go at the end.

**Guardrails** says how agents may change the project, whichever agent runs: paths they never edit without asking, commands they ask you about first, and commands they never run (`*` stands for any text). Sikemux enforces them where it acts for an agent: it refuses to run such a command for one, and its `git_commit` refuses a commit that touches a protected path. An agent's own shell commands follow them from its brief.

**Suggestions** holds what agents suggest for these settings. An agent never changes them itself: when it finds one missing or wrong, such as a Spring profile the tests need, it sends a suggestion with why, and what it ran to check. You tick the changes you want and apply them, or discard the rest. **Set up this project** asks an agent to read the repository, run the build and the tests, and suggest a full setup at once.

These settings stay on your Mac and are not written into the project.

## Project config

Check a `sikemux.json` into a project to add actions, tasks and a preview to the command deck (`⌘⇧P`). Sikemux shows each command and asks before running it.

```json
{
  "version": 1,
  "actions": [
    {
      "id": "check",
      "label": "Run checks",
      "command": "pnpm check",
      "placement": "terminal",
      "contexts": ["project"]
    }
  ],
  "tasks": [{ "id": "dev", "label": "Dev server", "command": "pnpm dev" }],
  "preview": { "url": "http://localhost:5173", "command": "pnpm dev" }
}
```

Agents can start, read and stop these tasks too. Tasks keep running in Sikemux's background process while the window is closed.

## Quitting

Terminals, agents and tasks keep running when you quit, and come back where they were. **Quit and Stop Everything** (`⌥⌘Q`) ends them.
