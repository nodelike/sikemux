A project is a folder: its editor, terminals, Git and search all work in that directory. Open one with `⌘O`, or from a terminal with the `sikemux` CLI:

```bash
sikemux .
sikemux src/App.tsx:42:5
```

Install the CLI from **Settings → Command line**.

Sikemux is also listed under **Open With** in Finder and in apps that use it, such as Raycast. A folder opens as a project, and a text file opens in the editor of the repository it belongs to.

Markdown opens as it reads, and a `.dbml` schema opens as a diagram of its tables with a line between each pair of columns that refer to each other; **Source** above it shows the text. Drag the canvas or scroll to move around, pinch or scroll with `⌘` to zoom, drag a table to move it (where you leave the tables, and the pan and zoom, are kept across restarts), and point at a table to light up its relationships. Double-click a table to jump to it in the source, or the empty canvas to fit everything in view. An HTML file opens as its source; **Preview** above it draws the page as a browser would, with the styles and pictures beside it, and its web links open in your browser.

## Moving around

Swipe sideways with two fingers on the trackpad to move between a project's tabs, one tab per swipe.

The rail on the right has three pages, picked from the icons at its foot or by swiping across the rail:

- **Agents**: the project's chats, then the earlier ones.
- **Terminals**: every terminal open in the project.
- **Files**: the files open in the editor, then the project's file tree.

The tree opens its folders to the file in front. Drag a file or folder onto a folder to move it there, or onto the tree's empty space to move it to the project's folder; its open tabs and unsaved edits go with it. Files dragged in from Finder are copied, on this host only. Dropped anywhere outside the tree, a chat or a terminal, Finder's files go to the terminal you are typing in, else to the chat in front.

Each project's row in the side rail shows the faces of its open agents, with a count of any past five, and a mark for how they stand together: working, waiting on you, or finished unseen. At the top of the **Agents** and **Terminals** pages, **All projects** counts what in other projects waits on you, and the Dock icon's badge counts it everywhere: a decision to make, such as a question, a permission or a pull request to merge; something only you can do, such as signing in, giving a secret or typing in a terminal; or something to fix, such as a failed turn or check. Work under way and finished turns don't count.

A terminal shows the folder its shell is in and how its last command went (running, done, or exit and its code) in its bottom corner. An SSH terminal's tab has a dot instead: green once connected, amber while connecting, red when it gave up. Closing a terminal's tab or pane, with `⌘W` or otherwise, ends its shell and anything running in it, without asking. A process's output tab is different: closing it leaves the process running.

## Project settings

Right-click a project in the side rail and pick **Project settings**, or run **Project settings** from the command palette, to open them in a tab of their own. Its pages:

- **General**: whether new chats start in a worktree, whether the project may start language servers, and the Space it sits under.
- **Processes**: the processes you added, each of which can be run, edited or removed, and **Add a process**, the same form as the run button's menu. Under them, the processes found in the build files, by folder, with a filter.
- **Git**: the repository the project's Git views use, when its folder holds several.
- **sikemux.json**: whether the project has one, whether you trust it, and any mistakes in it. **Open** shows the file in the editor.

## A folder with several repositories

When the project folder is not a repository itself but holds several, such as `backend/` and `web/`, the Git pane lists them. Star one, or pick it in [project settings](#project-settings), and it becomes the project's default: the Git pane opens it, the top bar shows its branch, the diff pane reviews it, and new agent worktrees are cut from it. When the folder holds only one repository, that one is used without asking. The choice stays on your Mac.

## Project config

Check a `sikemux.json` into a project to add actions, processes and a preview to the command deck (`⌘⇧P`). Sikemux shows each command and asks before running it.

```json
{
  "version": 1,
  "actions": [
    {
      "id": "check",
      "label": "Run checks",
      "command": "pnpm check",
      "placement": "terminal",
      "contexts": ["project"]
    }
  ],
  "tasks": [{ "id": "dev", "label": "Dev server", "command": "pnpm dev" }],
  "preview": { "url": "http://localhost:5173", "command": "pnpm dev" }
}
```

Processes go in its `tasks` list. Agents can start, read and stop them too. They keep running in the background while the window is closed.

`ship` lists your project's own commands that put work live, such as `"ship": ["make deploy", "scripts/release.sh"]`, matched by their leading words: an agent running one waits for you to allow it first, like a deploy ([what leaves this machine](/agents/permissions/#what-leaves-this-machine)). Claude Code, Grok and Hermes catch them; other agents catch them only when the script runs a program Sikemux knows, such as `vercel`.

`planFirst` lists paths, such as `"planFirst": ["server/**", "db/schema.sql"]`, whose change Sikemux suggests planning before it starts, when what you type names one. Migrations folders, `.proto` and OpenAPI files, a top-level `server/` or `api/`, and UI folders such as `components/` count in every project without it.

### The project's check

`check` says what proves the project's work sound, which a board slice needs before it passes **Built**. Give it a command, which Sikemux runs on each commit on the project's branch, as committed:

```json
{ "version": 1, "check": "pnpm check" }
```

Or name the CI workflows that count, when the project's CI is its check:

```json
{ "version": 1, "check": { "ci": ["CI"] } }
```

Sikemux then reads the code host's runs on the project's branch as pushed, instead of building it, so the agent's commit has to be on that branch and pushed: an agent whose commit isn't is told to land and push it, and the slice waits until it is. Every workflow named has to pass on the pushed branch's newest commit, which holds the agent's. Other branches on the remote, such as work in progress, decide nothing. A run that is cancelled, or that doesn't start within a few minutes of the push, counts as no verdict, so the agent marks the card done again to have it checked.

A check command runs only once you trust `sikemux.json`: the first commit it would check asks you. While the file has a mistake, Sikemux reads no check from it, and an agent working a slice is told what is wrong rather than that the project names none.

Without a `check`, Sikemux uses the test command the project's build files suggest at its root: the `test` script in `package.json` (not the one `npm init` writes, which only fails), `cargo test` for a Cargo project, `go test` for a Go module, pytest or Django's tests for a Python project, and Maven's or Gradle's `test`. It reads them once, when Sikemux starts. This check runs only on a slice's latest commit when its agent marks it done, never on every commit, and never marks the project as broken. `"check": false` turns it off.

### The changed page

When a slice's change touches the files a page is drawn from (`.tsx`, `.jsx`, `.vue`, `.svelte`, `.astro`, `.html` and stylesheets), Sikemux opens the page itself once the slice passes **Built**, in a new tab on its agent's desk, keeps screenshots of it at the tab's width and at a phone's and a tablet's as the slice's evidence, and closes the tab again. A tab the agent already has open on that site is used instead, and left open. It opens a server the agent started itself first. When the agent works in the project's own checkout, it opens the `preview` URL instead, if something is listening there, or else a server the project's run task started.

It opens a server's own address, never the route the change touched, and it never starts a server. It takes nothing when no server is running, when the only server is in another checkout, or when the window is closed. It also takes nothing for a page that needs you to sign in first, or for a change that isn't a web page. These screenshots show the running thing, but they don't count as an assertion's evidence. `"preview": false` turns this off.

Sikemux versions before this one reject `false` for either field and ignore the whole file, so leave the field out until everyone working on the project has updated.

## Quitting

Terminals, agents and processes keep running when you quit, and come back where they were. **Quit and Stop Everything** (`⌥⌘Q`) ends them, and Sikemux stays stopped. Chats stay open asleep, each on its saved conversation with its name and tab, and start again only when you open or write to one: messages from agents and triggers wait for it until then. A turn they were in shows as stopped. Sikemux's window says it is stopped, with **Start Sikemux**, and nothing starts it again until you press that or start it another way. If Sikemux ever stops answering, its window says so, with **Restart Sikemux**: that ends it and starts it again. Terminals end; chats pick up where they were.

On a Mac, the window's close button hides Sikemux as `⌘H` does. Click it in the Dock, follow a `sikemux://` link or run `sikemux open` to bring the window back as you left it.
