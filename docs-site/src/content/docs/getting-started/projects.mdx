title: Open a project
description: "Projects, and the sikemux.json that adds actions and processes to one."

A project is a folder: its editor, terminals, Git and search all work in that directory. Open one with `⌘O`, or from a terminal with the `sikemux` CLI:

```bash
sikemux .
sikemux src/App.tsx:42:5
```

Install the CLI from **Settings → Command line**.

Sikemux is also listed under **Open With** in Finder and in apps that use it, such as Raycast. A folder opens as a project, and a text file opens in the editor of the repository it belongs to.

Markdown opens as it reads, and a `.dbml` schema opens as a diagram of its tables with a line between each pair of columns that refer to each other; **Source** above it shows the text. Drag the canvas or scroll to move around, pinch or scroll with `⌘` to zoom, drag a table to move it (where you leave the tables, and the pan and zoom, are kept across restarts), and point at a table to light up its relationships. Double-click a table to jump to it in the source, or the empty canvas to fit everything in view. An HTML file opens as its source; **Preview** above it draws the page as a browser would, with the styles and pictures beside it, and its web links open in your browser.

## Moving around

Swipe sideways with two fingers on the trackpad to move between a project's tabs, one tab per swipe.

The rail on the right has three pages, picked from the icons at its foot or by swiping across the rail:

- **Agents**: the project's chats, then the earlier ones.
- **Terminals**: every terminal open in the project.
- **Files**: the files open in the editor, then the project's file tree.

The tree opens its folders to the file in front. Drag a file or folder onto a folder to move it there, or onto the tree's empty space to move it to the project's folder; its open tabs and unsaved edits go with it. Files dragged in from Finder are copied, on this host only. Dropped anywhere outside the tree, a chat or a terminal, Finder's files go to the terminal you are typing in, else to the chat in front.

Each project's row in the side rail shows the faces of its open agents, with a count of any past five, and a mark for how they stand together: working, waiting on you, or finished unseen. At the top of the **Agents** and **Terminals** pages, **All projects** counts the agents in other projects that are waiting on you.

A terminal shows the folder its shell is in and how its last command went (running, done, or exit and its code) in its bottom corner. An SSH terminal's tab has a dot instead: green once connected, amber while connecting, red when it gave up.

## Project settings

Right-click a project in the side rail and pick **Project settings**, or run **Project settings** from the command palette, to open them in a tab of their own. Its pages:

- **General**: whether new chats start in a worktree, whether the project may start language servers, and the Space it sits under.
- **Processes**: the processes you added, each of which can be run, edited or removed, and **Add a process**, the same form as the run button's menu. Under them, the processes found in the build files, by folder, with a filter.
- **Git**: the repository the project's Git views use, when its folder holds several.
- **sikemux.json**: whether the project has one, whether you trust it, and any mistakes in it. **Open** shows the file in the editor.

## A folder with several repositories

When the project folder is not a repository itself but holds several, such as `backend/` and `web/`, the Git pane lists them. Star one, or pick it in [project settings](#project-settings), and it becomes the project's default: the Git pane opens it, the top bar shows its branch, the diff pane reviews it, and new agent worktrees are cut from it. When the folder holds only one repository, that one is used without asking. The choice stays on your Mac.

## CI in the top bar

When the project's repository is on GitHub and you are signed in to it, the top bar shows CI for the newest pushed commit on your branch, next to the branch: the mark of the most pressing run (failed, then running, then queued) and how many runs are done of all, how many failed, or how many passed. Runs a tag on that commit started count too. Hover it for a card listing every workflow's run with its time, how long the rest should take, and **Re-run failed jobs** when one failed; click a run to open it in the Git pane.

## Project config

Check a `sikemux.json` into a project to add actions, processes and a preview to the command deck (`⌘⇧P`). Sikemux shows each command and asks before running it.

```json
{
  "version": 1,
  "actions": [
    {
      "id": "check",
      "label": "Run checks",
      "command": "pnpm check",
      "placement": "terminal",
      "contexts": ["project"]
    }
  ],
  "tasks": [{ "id": "dev", "label": "Dev server", "command": "pnpm dev" }],
  "preview": { "url": "http://localhost:5173", "command": "pnpm dev" }
}
```

Processes go in its `tasks` list. Agents can start, read and stop them too. They keep running in the background while the window is closed.

## Quitting

Terminals, agents and processes keep running when you quit, and come back where they were. **Quit and Stop Everything** (`⌥⌘Q`) ends them, and Sikemux stays stopped: its window says so, with **Start Sikemux**, and nothing starts it again until you press that or start it another way. If Sikemux ever stops answering, its window says so, with **Restart Sikemux**: that ends it and starts it again. Terminals end; chats pick up where they were.

On a Mac, the window's close button hides Sikemux as `⌘H` does. Click it in the Dock, follow a `sikemux://` link or run `sikemux open` to bring the window back as you left it.
