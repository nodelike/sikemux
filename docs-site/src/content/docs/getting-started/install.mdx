title: Install
description: "Install Sikemux on a Mac or on Linux, or just its core on a server."
---

## One line

```bash
curl -fsSL https://sikemux.com/install | sh
```

On a Mac this puts Sikemux in `/Applications`. On Linux it asks whether you want the desktop app or just the core, and suggests the core on a machine with no desktop. The app comes as the `.deb` or `.rpm`, as a pacman package on x86_64 Arch and Omarchy, or else as the AppImage, unpacked in `/usr/local/lib/sikemux/app` and added to your app launcher, on x86_64 and arm64.

For the nightly build, set the channel before `sh`:

```bash
curl -fsSL https://sikemux.com/install | SIKEMUX_CHANNEL=nightly sh
```

Without it, the line installs the stable release, so on a Mac running a nightly it asks before replacing it.

## Homebrew

On a Mac with [Homebrew](https://brew.sh):

```bash
brew install --cask nodelike/tap/sikemux
```

The cask follows stable releases. Sikemux then updates itself, as [Updates](/getting-started/updates/) describes, so `brew upgrade` leaves it alone unless you add `--greedy`. `brew uninstall --zap sikemux` also removes its settings, data and the core's launch agent.

## On a server

A Linux machine with no screen, such as a VPS or a spare box, can run just the core, which keeps agents working with nobody watching. If you already reach it over SSH, open an SSH terminal on it in Sikemux (`⌘⇧S`), then choose **Install Sikemux here** from the **⋯** beside it under **Hosts** in the side rail, or, with that host chosen, **Install Sikemux on** it in the top bar or ⌘N, which is all a host without Sikemux offers besides its terminal: the installer runs over your SSH in a new terminal tab, where you type `sudo`'s password if the server asks for one, and the server signs in to your account by itself. Otherwise, run the same line there and pick the core, or skip the question:

```bash
curl -fsSL https://sikemux.com/install | sh -s -- --host
```

`--app` picks the desktop app instead, and `--yes` takes every default without asking, as cloud-init and other scripts need. With no terminal attached, the installer asks nothing and installs the core on a machine with no desktop.

The core works on x86_64 and arm64 and needs no WebKit. The installer asks for `sudo` once: the core goes in `/usr/local/lib/sikemux`, and the `sikemux` command that runs it in `/usr/local/bin`, or in `~/.local/bin` when you are not root. With systemd, the core then starts at boot and restarts if it crashes. Last, it offers to sign the host in and prints a code: type it at app.sikemux.com/host or in Sikemux on your phone to add the host to your account, as [Your phone](/getting-started/phone/#adding-a-host-with-a-code) describes.

Once the server is signed in, your Mac and phone reach it with no SSH and nothing to approve: every device and host on your account trusts the others. The server has a row under **Hosts** in the side rail. **Projects** lists each repository on your account once, wherever its copies are: a project only the server holds names it at the end of its row, and one that both hold says how many hosts do. A project opens on the copy you last worked on. While it has more than one, the first row of its tree names the copy in front with its branch, and switches it; so does the **on** chip naming its host beside **New chat** and at the top of **Files**. Files, Git, Search and new chats and terminals use the copy in front, and the middle of the top bar shows its host and project. The tab rail lists the project's chats from every host, naming the host on each row that runs elsewhere, and a worker on another host stays under its lead. To get a copy on a host that has none, choose **Copy to** that host from the copy switch or the project's right-click menu: the host clones the repository into a new checkout with its own sign-in, or takes it from the copy in front when it cannot reach the remote. **This host** is offered too when only other hosts hold the project. The copy in front's uncommitted changes go over too, as a commit on top; untick **Bring uncommitted changes** in the copy switch to leave them. While the copy is made, the project's row shows where it is going; once done, it says whether it worked and how the uncommitted changes went, until you click it away. A copy runs as long as git keeps working and stops when git goes quiet for five minutes. The copy in front is never on a host out of reach while another copy is in reach. A folder outside Git stays a project of its one host. Choosing a host's row takes you to what is in front there. A host's **⋯** starts a chat or terminal there too, and opening a chat that runs there from the inbox, a notification or search chooses it. A server that already runs Sikemux needs nothing more: open an SSH terminal on it and the app asks it, over your own SSH and without prompting, which host it is, so a host already on your account keeps its one row under its own name, whichever SSH host reaches it. Until it answers, its row says **checking**; if SSH cannot reach it, needs a password or key it was not offered, or gets an answer that says nothing about Sikemux, the row says so and offers nothing, and it is asked again when its terminal reconnects. If it is not signed in, its row says so and its **⋯** offers **Sign in**, which signs it in over your SSH and names the host it added in a notice; if its core is stopped, **Start Sikemux**; and if it runs an older release, **Update Sikemux**, which updates it on the channel it follows and restarts its core. These run without a tab. If one stops short, the row, the top bar and the host's Sikemux tab say why, with a retry, until you dismiss it.

The core keeps the host's key and your sign-ins in `/var/lib/sikemux`, which only a `sikemux` group may open. The core runs as a member of that group and you do not, so the agents you run cannot read or change them. Keep your account out of the group, and run the core as yourself, not as root: agents run as whoever runs the core, and an agent running as root, or with `sudo` that needs no password, can read anything on the machine. The `.deb`, `.rpm` and Arch package set up the same store, though their window cannot sign in to your account yet: sign the computer in with `sikemux login` in a terminal. An AppImage cannot set up the store itself, so for the AppImage the installer asks for `sudo` once to put a core in `/usr/local/lib/sikemux` that can, unpacks the app beside it, and the app runs that core instead of its own. That core takes only the app unpacked there for Sikemux's own window, and updates both together. Run on its own, without the installer, the AppImage keeps no sign-ins, and with the installer's core there it cannot send prompts: start Sikemux from your app launcher.

The host needs no open ports: it connects out to Sikemux's relays over HTTPS and to your devices over UDP, so a firewall or security group can block all inbound traffic.

Later:

- `sikemux status` shows whether the core runs, whether it starts at boot, which account it is on, and how it updates. `sikemux status --json` also lists `problems`, each with a fixed `name`, what it `says` and the command or step that `fix`es it, such as `core-stopped` with `sikemux start`.
- `sikemux login` signs the host in, if you skipped it, and `sikemux logout` takes it off your account.
- Once signed in, a host stays with that account: after `sikemux logout` it signs back in only to the same one. To move it to another account, remove it from its account on any of your devices while it is still signed in, or run `sudo sikemux login`.
- The server keeps its core up to date by itself, as [Updates](/getting-started/updates/#on-a-server) describes; `sikemux update` updates it now.
- `sikemux restart` restarts the core in place, the way an update does, so its terminals and agents keep running through it; a chat in the middle of a request holds it until it can hand its agent over. `sikemux stop` ends the core and everything it runs; its chats stay open asleep, to start again on their saved conversations when you open or write to one.
- `sikemux help` lists every command.

## Download

The latest `.dmg` is on [sikemux.com](https://sikemux.com) and on [GitHub Releases](https://github.com/nodelike/sikemux/releases/latest). It is about 30 MB and needs macOS 11 or later on Apple Silicon.

On Linux the same release has a `.deb`, an `.rpm`, an Arch package and an `.AppImage`. These are the x86_64 names; arm64 has `_arm64` and `.aarch64` in their place, and no Arch package, so Arch on arm64 takes the AppImage:

```bash
sudo apt install ./Sikemux_<version>_amd64.deb                 # Debian, Ubuntu
sudo dnf install ./Sikemux-<version>-1.x86_64.rpm              # Fedora
sudo pacman -U ./sikemux-bin-<version>-1-x86_64.pkg.tar.zst    # Arch, Omarchy
chmod +x Sikemux_<version>_amd64.AppImage                      # any other distribution
```

A nightly's Arch package is `sikemux-nightly-bin`, with the version's hyphen left out, such as `sikemux-nightly-bin-0.6.1nightly.7-1-x86_64.pkg.tar.zst`.
